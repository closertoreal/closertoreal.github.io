# NEW · Сопоставление ПСД → схема СМР (итерация 2)

## 1. Назначение

Не просто выводить каталог документов и список шагов, а **визуализировать трассируемость** исходных строк сопоставленных перечней ПСД (НКНХ / ДГП) до действий схемы СМР. Аналитический результат: увидеть распределённые документы, шаги без назначенных документов, неоднозначные соответствия и возможные отсутствующие в схеме действия.

Пустой шаг или документ без шага **не является автоматическим доказательством ошибки**: процесс может быть вспомогательным, документ может не относиться к рассматриваемому виду работ, или детализация схемы может отличаться от детализации ПСД.

## 2. Данные

- Источник: загружаемый локально сопоставленный XLSM версии 6, лист с колонками `Код`, `НКНХ`, `Совпадение по тексту`, `Код`, `ДГП`, `Вопрос`, `Порядок`.
- Одна карточка = одна исходная **сопоставленная строка**, даже если есть обе площадки.
- Метки источников: `НКНХ + ДГП`, `только НКНХ`, `только ДГП`.
- Исходные коды, оба полных наименования, статус совпадения и вопрос сохраняются. Различия не скрываются: второе название раскрывается по кнопке «Комментарий / вопрос».
- Категории определяются по наличию дочерних кодов и не распределяются как документы.
- Файл остаётся в браузере (локальное хранилище + экспорт CSV). Полный корпоративный файл **не публикуется в GitHub**.

## 3. Четыре среза состава

| Срез | Операция |
|---|---|
| ∪ Все документы | Объединение записей перечней |
| ∩ Обе площадки | Пересечение - сопоставленные строки с обеими сторонами |
| Только НКНХ | Уникальные строки НКНХ |
| Только ДГП | Уникальные строки ДГП |

Это четыре альтернативных режима отбора из одной таблицы, а не четыре независимо хранимых набора документов. Переключение обновляет как список документов, так и распределение на схеме.

## 4. Юридические функции ИД

Для каждого конечного документа автоматически предлагаются независимые признаки:

- `done` - факт выполнения конкретных видов и объёма работ;
- `quality` - требуемое качество и соответствие проекту и НТД;
- `them` - участие конкретных исполнителей;
- `next` - возможность производства последующих работ.

Автоматические признаки устанавливаются **только при наличии терминологических оснований**, а не путём заполнения всех четырёх полей у каждого акта. Отсутствие положительной метки = **не установлено**, а не обязательно «нет». Например, приказ о назначении не равен доказательству фактического участия исполнителя.

Тег на стороне документа и тег на стороне шага открывают одинаковое определение. Редактор в карточке документа допускает `Авто / Да / Нет / Не определено`. Правки хранятся отдельно от текста XLSM. Метки шага - логическое объединение меток назначенных документов с подсчётом количества документов на каждую функцию.

## 5. Распределение и связи

- Смысловой классификатор `classifier.js` предварительно предлагает шаг по типу и назначению документа; для неоднозначных и слабых совпадений фиксируется неопределённость.
- На экране справа **сохранены 35 шагов** исходного процесса, порядок основных стадий, последовательности, параллельные направления и контуры возврата.
- По нажатию «Распределить по шагам» документы и их теги отображаются на нужных карточках; анимация группируется по шагам во избежание 1388 одновременных перелётов.
- По клику на документ слева подсвечивается связанный шаг справа.
- По клику на шаг справа открывается **модальное окно** с документами и кнопками «Показать в реестре». Третья колонка не создаётся.
- По клику на тег с любой стороны открывается определение, а не меняется значение.
- Неопределённые документы остаются в отдельном наборе кандидатов на уточнение; шаги без назначений имеют явную пометку.

## 6. Контроль, ограничения и приёмка

1. В XLSM версии 6 импортируются все исходные строки (в том числе 248 вопросов и категории) с сохранением порядка и отсутствующих сторон.
2. Каждая конечная строка показывается ровно один раз, несмотря на присутствие в двух перечнях.
3. Режим ∪ должен охватывать все конечные документы, ∩ только общие, два уникальных среза не пересекаются; переключение влияет на граф.
4. Автоматическая классификация срабатывает для известных типов и показывает уверенность, но **не называется экспертно подтверждённой**.
5. В схеме видны направленные переходы этапов, параллельные группы, 35 шагов и сгруппированные по каждому шагу метки.
6. Работающая связь слева → шаг справа и справа → полный список документов → исходная строка.
7. Клик по тегу показывает определение, редактирование метки требует отдельного действия.
8. Экспорт CSV сохраняет оба названия, коды, вопросы, шаги и четыре функции ИД.
9. До получения экспертного подтверждения нельзя объявлять все шаги/документы полностью корректно распределёнными.
10. Исходная схема СМР и протокол не перезаписываются.

Содержимое корпоративного XLSM **не встроено** в опубликованную страницу: при первом использовании загрузи файл локально, дальше он и ручные правки сохраняются в этом браузере (пока позволяет объём localStorage). При смене устройства нужен экспорт/новый импорт.

## 7. Состояние работ и тесты

Стадия: **MVP с предварительной автоматической классификацией**. Проверены синтаксис JavaScript и тестовый запуск DOM-логики с 35 шагами, модальным окном, 40 демонстрационными строками и четырьмя режимами отбора. Полное отображение и анимацию в реальном пользовательском браузере необходимо проверить отдельно, включая импорт исходного XLSM.
